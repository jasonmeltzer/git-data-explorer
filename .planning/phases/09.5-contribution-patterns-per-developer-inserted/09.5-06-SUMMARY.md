## Decisions Made

- **AI-power-user gets BOTH frequency AND lines multipliers post-AI.** D-21 frames AI adoption as both volume-up (more PRs/commits) AND shape-change (smaller commits). The plan Edit C explicitly specifies a 0.7x linesPerCommit multiplier alongside the 2.5x frequency multiplier — implemented verbatim.
- **PreAiBaseline calls buildDeveloperMonthly but does NOT pass archetypeMix.** This is the D-22 control-group invariant: per-dev rows are emitted (necessary for Phase 9.7 schema parity), but with aiMarkerMonth=null, isPostAI is false for every month, so all four archetype branches collapse to constant multipliers. Result: per-dev series are flat, no shape change. Test 4 verifies this empirically.
- **Test 2 uses persona[1] (Azure Bear), not persona[0] (Amber Bear).** The plan verbatim test sketch used `developerMonthly[0].authorLogin` (Amber Bear, lexicographic-first authorLogin). However, SmallStartup `includeDominantWindow: true` (default) elevates personas[0] to ~50% share for 3 pre-AI months, which inflates the AI-power-user pre-AI mean prCount (~8.3) above what the 2.5x post-AI ramp produces (~7.8). Net result: meanPost is NOT > meanPre times 1.5 because pre is artificially boosted. Fix: use the second AI-power-user (persona[1] / Azure Bear), which has the same archetype but is not the dominantWindow target. This is a test-design refinement, not an archetype-shape bug — the AI-power-user IS ramping post-AI; persona[0] pre-AI was artificially inflated by an orthogonal feature.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test 2 (AI-power-user ramp) failed when using persona[0] due to dominantWindow confounder**

- **Found during:** Task 3 (initial test run)
- **Issue:** The plan verbatim test sketch asserted `meanPost > meanPre times 1.5` for `bundle.developerMonthly[0]` (Amber Bear, lexicographic-first persona). The test failed: meanPost = 7.83, meanPre times 1.5 = 12.5 (so meanPre ~ 8.33). Investigation: SmallStartup `includeDominantWindow: true` (default) elevates personas[0] to ~50% of the activity for 3 pre-AI months (months index 3-5, late pre-AI window). This inflates persona[0] pre-AI mean prCount well above its base 4 PRs/month -> ~8.33. Meanwhile its post-AI mean is the AI-power-user 2.5x multiplier x 4 ~= 10. Net: meanPost is only ~1.0x meanPre, not ~2.5x.
- **Fix:** Changed the test to use the SECOND AI-power-user (persona[1] / Azure Bear) by sorting distinct authorLogins lexicographically and taking index 1. Per D-22, both persona[0] and persona[1] are AI-power-user archetype, so the test asserts the same archetype invariant. persona[1] is not the dominantWindow target (dominantLogin = personas[0].login), so the test reads the clean AI-power-user shape.
- **Files modified:** `packages/research/server/__tests__/test-data-gen.test.ts` (still in Task 3 commit, not a separate deviation commit — fixed before the test commit landed).
- **Why not weaken assertion:** The 2.5x ramp is the D-21 narrative anchor; weakening to allow ~1.0x masks the AI-power-user signal entirely. Choosing a non-overlapping persona is a cleaner fix.
- **Inline-comment in code:** The fix includes an inline comment explaining the persona[1] choice for future readers.
