# Phase 04.1 Plan 02: Collection Engine Bug Fixes Summary

**Five collection engine bugs fixed: SSE silent event drops, upsertAuthor crash on null row, skipCurrent race condition, stale depthTarget after incremental sync, and misleading outer progress event**

## Performance

- **Duration:** 7 min

- **Completed:** 2026-03-27T04:14:00Z
- **Tasks:** 2 (both committed together as unified TDD cycle)
- **Files modified:** 6

## Accomplishments

- Fixed SSE client silently dropping 'status' events — server emits 'status' type but client only listened on 'progress'. Added 'status' addEventListener and wrapped both listeners in try/catch. Extended `CollectionProgressEvent` type with `'status_snapshot'` variant.
- Fixed upsertAuthor non-null assertion crash — replaced `row!.id` with a guard that throws `Error("Failed to retrieve author row after upsert for login=...")` providing actionable diagnostic instead of opaque TypeError.
- Fixed skipCurrent race condition — added `if (!this._isActive) return` guard so calling skipCurrent on an idle queue does nothing instead of calling engine.abort() on a non-running engine.
- Fixed stale depthTarget after incremental sync — both collectCommits and collectPRs incremental paths now call `upsertCollectionState` to update `depthTarget` to the current boundary before marking complete, preventing false full-collection triggers on depth shrink→expand cycles.
- Removed misleading outer `page_complete` event with `itemsInPage: 0` from collectCommits month loop. The inner `collectCommitsForMonth` already emits accurate per-page events with real item counts.

## Decisions Made

- BUG-04 depthTarget update must happen in BOTH collectCommits and collectPRs incremental paths. The scenario that triggers the bug: user collects at 6mo depth → reduces to 3mo → incremental runs (3mo >= 6mo → false, wait... 3mo-ago date is LATER than 6mo-ago date, so 3mo-ago >= 6mo-ago = true) → depthTarget stays as 6mo-ago → user expands to 4mo → 4mo-ago < 6mo-ago (stored prevTarget) → full collection unnecessarily triggered. Fix: after incremental sync, set depthTarget = current depthBoundary.
- BUG-03 test strategy: avoid calling startBatch() in skipCurrent tests to prevent the module-level `_transitionDone` flag from being set prematurely and causing the legacy-transition tests to fail due to test ordering.

## Issues Encountered

- BUG-04 initial tests passed trivially because they used the same boundary as the existing depthTarget — not actually testing the bug. Rewrote tests to use a deep old boundary (6mo) with a shallower new boundary (3mo) to correctly verify depthTarget is updated to the NEW value.
- BUG-03 test isolation issue: first test design called `queue.startBatch()` which set the module-level `_transitionDone = true`, causing the pre-existing "resets mid-collection legacy repos" test to fail. Fixed by rewriting the test to not call startBatch().
